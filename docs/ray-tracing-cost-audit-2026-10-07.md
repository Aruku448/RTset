# 光追内部成本审计（2026-10-07）

## 当前结论与证据边界

已知末段测试（854×480，DI 开启、suffix 关闭、GI=4、太阳采样=4、体积质量=2）的光追 dispatch 中位数为 **16.837 ms**，占 mod GPU 命令区间约 86%。该数值包含下面所有内部工作，不能按源码长度或静态指令数分配毫秒。

### 能支持的结论

- 第一轮前后 baseline 漂移 **0.21%**；第二轮 **4.23%（约 0.838 ms）**。第二轮月亮、POM、PBR 的小差值低于整轮漂移尺度，不足以判断它们的精确净成本；太阳出现负收益也不能作为其固有性能结论。游戏时刻、天气、动画和编译资源分配未完全固定。
- 当前场景的较大边际变化：全部可见性阴影约 **5.204 ms**、GI 整套续追约 **4.741 ms**、相机体积约 **4.628 ms**；面光源约 **2.235 ms**、天空 NEE 约 **2.739 ms**。其中阴影、体积、GI 阶段频率下降约 21–28%，BLAS 也随之变慢，实际 GPU 总区间只分别减少约 **4.334 / 4.010 / 3.977 ms**。应把它们理解为默认调频下的实测收益，不能按 MHz 比例换算“纯算法耗时”。
- static-only 动态差值对照约 **0.126 ms**；第一轮 no_restir 对照比 baseline 高约 **0.100 ms**。ReSTIR 实际 mode 一直为 0，因此这一轮**没有测量开启 DI/suffix 的成本或收益**，11 个候选只是未启用的设置值。
- 主射线完整材质 **3.045 ms**，最小命中路径 **3.028 ms**，核心频率均约 1247 MHz。当前视角未测出明显主命中材质附加成本；不能推广到满屏复杂 POM 材质。最小路径仍包含遍历、alpha any-hit、miss/最小 hit、payload/AOV 和输出，不是 RT 单元独占时间。
- 当前正常 GPU 命令耗时约 **22.2 ms**，光追 dispatch 约 **19.8 ms（89%）**，动态 BLAS 约 **1.32 ms（6%）**。本次未恢复 BLAS 更新预算限制。

### 硬件还是算法

**证据支持：当前画质配置的算法工作量是优先优化方向，GPU 同时接近当前功耗预算。** 第一轮基线 GPU busy 中位数 93%、核心 2444 MHz、功耗 207.5 W，设备功耗 cap 212 W；edge 56°C / hotspot 80°C。显存使用约 8.18 GiB / 16 GiB。未见这一基线阶段的显存容量耗尽，也未出现上一轮 AFK 的半频状态；这不等于已经排除温度限制或证明 RT 单元、ALU、显存带宽饱和。

消融后工作量下降，GPU 调频和功耗同时下降；硬件调频会改变“省了多少毫秒”，还会拖慢未修改的 BLAS/TLAS。需要固定频率或硬件性能计数器，才能进一步拆解 RT 相交、shader ALU、寄存器压力、缓存及内存 stall。本次未改 GPU 频率/功耗设置。

优化优先级：先拆分并减少体积遮挡、天空/面光源可见性及 GI 后续顶点的重复工作；再检查动态 BLAS 构建。POM/PBR 和动态差值在当前场景的证据不足以列为首要瓶颈。降低采样或删掉通道会改变画面；消融本身只用于诊断，不是已完成的质量保持优化。

完整证据：`docs/profiling/2026-10-07-ray-cost-audit-measurements.json`，包含每阶段 GPU/P95、所有硬件统计、基线漂移及配置。原始 GPU 日志和硬件 JSONL 保存在该 JSON 指出的两轮目录。

## 按执行顺序拆分

| 步骤 | 实际工作 | 当前预算或上限 | 性能影响及不能混淆的部分 |
|---|---|---|---|
| 像素初始化 | 相机射线、Sobol 基础状态、AOV、ReSTIR 输出清零 | 每像素一次 | 与分辨率线性增加；不是光追硬件相交 |
| 主射线 | TLAS/BLAS 遍历、alpha any-hit、closest-hit | 1 条/像素 | 植被等 cutout 可使一条射线触发多次 any-hit；遍历基准仍包含这些 shader 与输出写入 |
| 命中材质 | 7 个 vec4 的逐三角形材质布局、UV 插值、atlas、法线/粗糙度/发光、光学参数 | 每次路径命中 | closest-hit 不只是返回交点；也承担材质读取和计算 |
| POM | 高度读取、搜索、细化 | 最多 32 搜索步 + 5 细化 + 起始采样 | 双线性高度每次读取四个 SSBO texel，条件成立时最多约 152 次高度 texel 读取；平坦/禁用材质提前返回。不是每次命中都执行上限 |
| PBR companion | normal/specular/emission/AO/wetness 解码 | 每次有对应贴图的命中 | 与 POM 共享输入；关闭 PBR 会改变 BSDF 和后续路径，而不只是减少读取 |
| BSDF 准备 | GGX/介质界面、Fresnel、能量与 lobe 概率 | 每个表面顶点 | 已复用 receiverEnergy；后续多个 NEE 仍分别求 BSDF |
| 太阳 NEE | 分层太阳盘采样、透射 LUT、BSDF/MIS、阴影 | 主命中 4 次，后续每个顶点 1 次 | 5 段路径最多 8 次基础太阳阴影查询，条件不满足则不追踪 |
| 月亮 NEE | 独立采样域、月相/辐射、BSDF/MIS、阴影 | 每个顶点最多 1 次 | 5 段最多 5 条；夜晚、方向及余弦条件决定实际数量 |
| 面光源 NEE | light tree 选灯、三角形采样、发光材质、BSDF、可见性 | 每个非透射顶点一次 | 每次选灯最多遍历 64 层树；实际树深由场景决定 |
| ReSTIR DI | 新候选目标评估、reservoir 合并、时空旧候选、选中灯可见性 | 当前 11 新候选 + 最多 3 旧 proposal | 不是 11 条阴影射线；候选增加选灯、发光材质及目标函数工作。仅静态、粗糙、非透射主表面满足复用资格 |
| 天空 NEE | 重要性采样、可见性、天空辐射、MIS | 仅主表面最多 1 次 | 当前硬件 CDF 开启，重要性分支还会向独立 skyCdfAS 发起最多 1 条采样射线（payload=3），不是场景阴影；关闭天空 NEE 仍保留 BSDF miss 的环境光 |
| 动态差值 | 动态遮挡后再做 static-only 可见性，计算光照 delta | 条件触发时每个相关 NEE 多 1 条 | 不是 BVH 相交必需；NRD 关闭时原逻辑仍执行，需单独对照 |
| GI/反射/透射续追 | BSDF 散射、介质吸收、RR、下一顶点全部命中和 NEE | GI=4 → 最多 5 个路径段 | 提前 miss/RR/throughput 截断会降低实际数量；`no_gi` 去除整个后续工作，不等于只测相交 |
| 相机体积 | 物理/legacy 积分、太阳/月亮遮挡、局部发光体采样 | 质量 2：8 积分点；物理灯光体积 2 次采样 | 当前 volumeShadowSamples=0 表示全部积分点阴影，**不是关闭阴影**；太阳和月亮分别最多 8 条，局部发光体最多 2 基础 + 2 static-only 条 |
| 信号输出 | HDR/AOV、距离、动态 delta、颜色转换 | 每像素 | 固定输出成本；与后面的 FSR/后处理 pass 分开 |

忽略条件裁剪时，当前 5 段路径的几何续追最多 5 条，表面基础 NEE 阴影最多 8+5+5+1=19 条；static-only 重追踪可能再增加最多 19 条。物理体积在质量 2、完整阴影预算下还有最多约 20 条。这个条件上界约 **63 条场景射线/像素**，另有最多 1 条 sky CDF 采样射线。它不是实际平均射线数，也不代表每条射线相同成本；alpha/translucent any-hit 的交点处理次数不能用这条射线数量上界约束。

suffix 当前关闭，不计入上述预算。开启 suffix 时同一像素会评估多个条件后缀，主射线/首个后缀交点虽已有缓存，后续可见性及续追仍重复；应另设固定 suffix 实验。

## 对照采样

工具 `tools/profiling/run_ray_cost_audit.py` 在已进入场景的 RTest 中依次切换 profile，每项等待匹配的 GPU 日志、稳定 12 秒、采样 45 秒，并每秒同时读取 AMD sysfs 硬件数据。结束、超时、Ctrl+C 或 SIGTERM 会恢复原审计配置。不会修改 GI、灯光、ReSTIR 和 BLAS 更新设置。

```bash
python3 tools/profiling/run_ray_cost_audit.py
```

默认 15 个阶段（14 profile + 回到 baseline），约 14–16 分钟，加上 shader/资源重建等待。首次可缩小为：

```bash
python3 tools/profiling/run_ray_cost_audit.py \
  --profiles baseline no_shadow_rays no_dynamic_delta no_volume no_restir no_gi baseline
```

测试保持相机、窗口、场景对象及配置不变，关闭 debug/offline 功能。光照时刻、天气、动画和其他 GPU 程序也可能造成漂移；脚本记录每阶段的设置，并对比前后 baseline。每阶段结果位于 `tmp/profiling/ray-audit-*/`，包括 GPU 原始日志、硬件 JSONL、设置、逐步骤统计和边际差值。

**空闲限帧必须设为仅最小化，并让游戏保持前台。** 本实例原 `options.txt` 为 `inactivityFpsLimit:"afk"`，保持相机不动会触发 AFK 限帧，随后 GPU 时钟和功耗降低。不同频率下的原始毫秒不能直接作为算法差值。工具已加入 AFK 配置预检查。

`baseline.trace_ms − profile.trace_ms` 是该实验条件下的边际差值。差值可能为负，因为编译、寄存器、缓存及路径分布也会变化。**不要把各个差值相加**；多个 profile 去除的工作有交集。`primary_material − traversal_only` 只在两者采样场景稳定时近似反映主命中材质的附加成本。

## 硬件与算法判别

若关闭阴影后耗时大幅下降而关闭 POM/PBR 差值很小，证据支持可见性查询及其 hit/any-hit 占重成本；不能直接断言 RT 单元达到峰值。若关闭 POM/PBR 下降明显，则材质读取/计算或它对后续路径的影响值得优先检查。若 no_volume 显著下降，要再用 shadow 对照区分积分算术与遮挡射线。

同步频率/功耗/温度数据可判断运行期是否存在低频、接近功耗上限或温度变化；GPU/VRAM busy 是设备级指标，不能直接给出 shader ALU、RT 单元、寄存器或缓存 stall 的独占占比。要做这些硬件归因还需对应硬件性能计数器。

先前硬件采样没有覆盖游戏运行期，这次工具将硬件采样与 profile 放在同一个循环，避免把桌面数据用于游戏结论。
