# 材质与发光源数据流优化（2026-10-07）

## 依据与范围

成本审计的同场景基线约 19.8 ms，完整主射线命中材质路径约 3.045 ms。消融显示后续光照、体积与多段路径贡献较大；不同实验 GPU 频率不同，差值不能简单相加。本轮据此处理实际代码中的重复比较、复制和光源计算，没有新增 GPU 中间缓冲或提交。

动态 BLAS 的逻辑构建数与 queue submit 数并非同一指标。此前已经将独立 BLAS 构建打包；本轮继续保留每帧动画更新与现有同步修复，不通过降低更新频率取得收益。

## 优化前后

| 步骤 | 原逻辑 | 新逻辑 | 生效条件 |
|---|---|---|---|
| 动态模型材质 | 每个模型先整数组比较，变化模型再按三角形比较；上传后整数组复制到缓存 | `Arrays.mismatch` 跳过未变前缀，合并连续变化行；同一变化区间写 mapped buffer 和独立缓存 | 动态材质发布 |
| 缓存分配 | 每次变化都重新分配整个材质快照 | 数组长度稳定时复用快照；首次、长度变化时分配 | 动态模型/物品材质 |
| 表面/体积光源可见性 | 实际和排除动态物体的查询分别计算方向、距离、端点安全范围 | 准备一次短生命周期 `EmitterVisibilityRay`，两次查询共用 | 面光源采样；第二次查询确有需要时才节省重复计算 |
| 旧体积发光源 | 实际/静态可见性分别调用相同的几何、PDF、相位与发光纹理评估 | 一次求未遮挡贡献，分别乘实际/静态可见性 | 旧体积路径；当前物理大气路径不享有这一项收益 |
| PBR 发光伴随纹理 | 读取描述与像素后才判断发光功能开关 | 开关关闭时先返回 fallback | PBR 发光关闭；当前开启设置不享有这一项收益 |

缓存仍拥有独立数组，不能直接引用捕获数组，否则捕获侧修改会使差分失效。mapped buffer 写入区间依旧先登记刷新覆盖；强制重建、首次发布或布局变化仍完整上传。全局是否映射材质缓冲的预检查仍保留，以避免全场景未变化时映射；因此不是消除了所有重复扫描。

以测试中的 100 行材质、仅一行变化为例：缓存复制从 11,200 字节变为 112 字节，后续帧复用同一快照数组。这里是确定的逻辑复制量，不能换算成实测毫秒。GPU 材质上传早已按变化行执行，本轮主要进一步削减 CPU 端快照复制、分配及重复扫描。

旧体积公式从 `((source * visibility) * phase) / pdf` 提取成 `(source * phase / pdf) * visibility`；数学等价，但浮点乘法顺序变化。查询参数复用不减少可见性射线数量、改变采样 PDF 或光源选择分布。

## 验证与限制

- 200 组随机 scratch 布局、250 组材质全量上传差分对照，以及 200 次连续变化的缓存复用、捕获数组隔离、长度变化测试通过。
- 200,000 组体积因式分解数值对照，最大相对浮点差异 `2.433342831481519e-7`。
- 实际 AS 屏障契约、shader/render math、ReSTIR 条件数学和大气高度 502,997 组 oracle 通过。
- 14 种成本消融、不同 reservoir/大气组合共 98 个 SPIR-V 模块编译通过，全部独立通过 `spirv-val --target-env vulkan1.2`。
- JAR 构建和 `git diff --check` 通过。日志在 `/tmp/rt-dataflow-tests.log` 与 `/tmp/rt-dataflow-final-tests.log`。

没有本版本的游戏 GPU A/B 耗时或长期稳定性结果。短生命周期射线参数跨 trace 调用保留可能影响寄存器占用，编译器也可能已经消除一部分重复运算；源码调用减少不等于确定加速。重启后应固定场景、窗口尺寸、相机与设置，记录基线/新版/基线的 trace、command、upload 和 GPU 频率，再判断收益。
