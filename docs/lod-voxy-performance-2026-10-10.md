## 体素数据复用与真正粗化

`RayTracingTerrainLod.Builder` 为单 worker 所有。以 section 原点和内容指纹索引缓存，并在命中时验证源数组身份或内容，防止指纹碰撞复用错误数据。

- 原生 section 只在缓存未命中时执行不透明三角形筛选与 triangle/AABB SAT，生成 4³ 个 4 块宽样本。
- 每个样本保留六方向材质代表及占据代表、面积与稳定 tie，父级不读取已经剔除内部面的输出网格。
- 对 4³ 样本做 2×2×2 归并，得到 2³ 个 8 块宽样本，L1/L2 共用同一缓存条目。
- L1 仍为 32³ 世界范围 / 8³ 格子；L2 改为 64³ 世界范围 / 8³ 格子，格子宽度从原来的 4 块变为 8 块。
- 缓存按 LRU 限制为约 64MiB、最多 1024 条目；计费包含样本持有的原生顶点与材质数组。超过容量的单个 section 可以构建，但不进入缓存。
- world generation 改变时由 worker 清空缓存；内容变化使用新缓存键。旧条目受 LRU 与容量限制，不会无限保留。
- 自定义模型越出 16³ section 范围，或输入原点不对齐时，回退为在目标节点范围内直接采样，保留原有跨边界覆盖。

这里仍是**表面体素 mip**，没有完整方块状态或内部实心体积。占据采用子样本并集，方向材质按原有面积/tie 规则选取，避免把未捕获的体积凭空补齐。L2 轮廓会比旧版更粗，需要游戏画面确认可接受程度。

## 构建内存和面片合并

worker 复用节点选样数组、扫描面 mask、patch 描述与输出临时坐标/UV。输出数组由新 Mesh 独占，构建结束不再整份 clone；公开访问与外部重建仍保持复制边界。

新 mesher 扫描六方向外露面，沿两个切向轴归并兼容矩形。当前只归并 **UV 为常量且全部 28 个材质字段一致** 的面。普通 atlas 纹理面保持独立，避免扩大 quad 后拉伸纹理、跨 tile 采样或改变 PBR 映射。要获得 Voxy 那种普通纹理面的完整 greedy 收益，需要进一步增加 tile 重复采样契约，本次没有假装已实现。

## 调度和取消

- 提交前选出距离最近的 K 个候选，K 不超过本帧构建预算和调度器剩余容量；不再按 HashMap 遍历顺序决定构建位置。
- 优先级按 32 块距离桶排序，同桶优先粗层，再比较实际距离和稳定序号。队列与提交端使用同一规则。
- 只保留最佳 K 项，不对完整层级做全量排序；队列满时跳过候选扫描。
- worker 使用命名 daemon 线程，Java priority 3，降低与渲染线程竞争。
- 原生采样每 256 个三角形检查取消，section 之间也检查；清空任务时移除 executor 实际排队对象。
- 过期 worker 的失败不再进入失败队列；渲染线程再核对 token，避免旧失败把新请求标为 blocked。
- worker 从并发输入包取得 NodeKey 与快照，不再读取渲染线程正在修改的普通 key HashMap。

已排队请求的距离是提交时快照；没有在每次相机移动时全量重排队列。

## 发布和材质地址复用

新增配置 `terrainLodPublishBudgetKiB`，默认 2048 KiB，范围 64–65536 KiB。

- 调度器消费完成结果前检查整节点字节量，不拆分几何与材质。
- 保留原有约 1 秒的批次节流。每批最多接纳 8 个完成节点或配置的更大 build budget，并受字节预算约束；该数量限制与本帧启动构建数分开。
- 首个超预算节点可以单独接纳，避免永远卡住队列；后续结果留在队列中并继续占容量，形成背压。
- 当前组合尚未完成时停止接纳下一批，避免后台结果不断改变 serial，使组合结果过期或积累成更大的发布。
- 远景缓存恢复共享剩余字节预算；缓存 payload 身份没变时复用 Node，不再每次选择都复制整份代理数组。
- 远景与当前原生地形的重叠检查，改成一次建立父节点集合后查 membership，替代每个代理遍历全部原生 sections。
- 同一 ready Node 复用其 `SectionGeometry`，不再每次组合都复制、哈希、重新建立未变化粗节点；材质增量写入能通过身份检查跳过这些节点。
- LOD 场景组合使用保留地址的材质布局更新，不因碎片阈值触发全场景 compact；存活 native/coarse section 保持材质地址，空洞继续用于新节点。原生场景更新仍保留既有压缩策略。

保持地址会保留部分材质缓冲空洞，换取增量更新；LOD 不保证立即缩小材质缓冲显存。字节预算针对**新接纳 mesh 数据**，不涵盖相机移动引起的 cut 变化、原生 streaming、全部 metadata、BLAS/TLAS 构建和 GPU fence 等待，不能当作严格的帧时间上限。

## 日志与构建状态

原有 `RTest terrain LOD` 日志增加：

- `admitted_mesh_bytes`：当前 tick 接纳的 mesh 字节。
- `voxel_cache_hits` / `voxel_cache_misses`：worker 累计缓存命中与未命中。
- `voxel_cache_bytes`：缓存计费字节数。

这些日志仍按既有每 120 帧输出，因此 `admitted_mesh_bytes=0` 只表示采样 tick 未接纳，不代表此前没有发布。缓存命中率可用两个采样点之间 `Δhits / (Δhits + Δmisses)` 计算。由于越界模型会走原始采样，缓存命中不一定意味着该 section 省掉了全部三角形扫描。

执行了 `./gradlew compileJava --offline --console=plain`，编译通过。现有 LOD 契约里与合并后面数有关的断言已同步更新；本轮没有新增或运行测试，也没有重启游戏。实际构建时间、材质写入耗时、缓存命中率和画面质量仍需新进程加载制品后观察，尚无同场景性能提升倍数。
