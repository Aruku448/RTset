# RT 渲染数学审计与加速顺序

日期：2026-10-04。检查对象为当前工作区源码；没有修改运行代码、配置、构建或部署 mod。

## 结论

可以通过数学减少渲染成本。优先消除无贡献射线和重复材质计算，然后尝试更高效的采样估计器。不能把代数运算减少直接换算成 FPS；当前缺少同场景 GPU A/B 数据。上一轮的材质 early-out、GGX 能量表复用、光树交叉相乘和体积公共项提取已经实现，本报告不重复计入收益。

审计覆盖表面 BSDF、NEE/MIS、随机采样、俄罗斯轮盘、折射与色散、草木响应、有限段介质积分、太阳/月光遮挡、局部体积光、POM、光树、材质地址管理与场景窗口更新。它不是所有输入下的形式化正确性证明，也不覆盖驱动、NRD/FSR 内部算法的正确性。

## 必须先处理的光学问题

### 全反射

`RayTracingShaderRaygen.java:1632` 的 refract 失败后，镜面延续在 `:1925` 仍乘 Schlick 近似。IOR 比 1.5、入射余弦 0.5 的例子发生全反射，Schlick 却给 0.07，应反射的权重为 1。需要统一反射分支概率和实际能量权重，不能只改变分支选择。

### 粗糙透明太阳 MIS

`:1668` 的太阳 PDF 评价对透明材质采用镜面概率 1，但 `:1636` 的实际延续采用 Fresnel 分支概率，`:1527` 的环境命中又使用实际 mixture PDF。两端权重不再互补。修复应共享真实 proposal 定义，并保留光源样本数 N。平滑 delta 界面走独立规则。

其它限制：当前 insideMedium 布尔状态不能表达嵌套介质；折射的 eta² 与 transport mode 尚未完整统一；RGB hero channel 近似不等于完整光谱。固定 PDF 下限也可能造成低 PDF 区域的偏差。详细证据见 [表面输运审计](rt-math-transport-audit-2026-10-04.md)。

## 体积遮挡：收益较大的数学候选

当前 `RayTracingShaderRaygen.java:532` 对相机有限段做 4/8/16 步积分。令每步无遮挡直接散射 RGB 贡献为 aᵢ，RGB 透明遮挡为 Vᵢ，则当前离散目标为：

```
I = Σ aᵢ Vᵢ
I₀ = Σ aᵢ
Î = I₀ + (1/K) Σ[k=1..K] aⱼₖ (Vⱼₖ − 1) / pⱼₖ
```

只要所有非零贡献都有正采样概率 pᵢ，E[Î]=I。可以继续确定性计算介质、透射率与多重散射，仅抽样直接光遮挡残差。太阳和月光可以共用采样位置，但联合概率必须覆盖两者，且各自保留 RGB 阴影与光源贡献。天空遮挡修正也必须按自身源项保留。

N=8、K=2 时，太阳遮挡查询数量可减少 75%；这不是整帧耗时减少 75%。遮挡残差在强光柱场景可能有较大方差或负的单次修正。当前相机大气并未自动享受表面 NRD 历史，必须处理时间稳定性与 disocclusion，不能靠强行 clamp 消除噪声而仍宣称无偏。

这与 [PBRT 的蒙特卡洛效率讨论](https://pbr-book.org/4ed/Monte_Carlo_Integration/Improving_Efficiency)一致：应比较方差与成本，而非只比较样本数。此处公式针对现有有限步和，不证明连续介质积分精确。

## 介质透射：前缀积分与解析式

`physicalAtmLocalTransmittance`（`:1165`）每次用四个中点查询介质。若光学深度 LUT 定义为沿同一射线到共同大气边界的积分 D，则：

```
τ(A→B) = D(A,ω) − D(B,ω)
T = exp(−τ)
rB = sqrt(rA² + 2 rA μA d + d²)
μB = (rA μA + d) / rB
```

两端必须使用各自球面局部方向余弦，不能把 μA 直接用于 B。地面相交、边界分支、高度 clamp、介质/LUT 更新一致性都要匹配。短距离减去两个接近的大值会丢精度，需回退或专用局部积分。两次 LUT 查询不一定比四次紧凑介质表查询更快，且插值结果不同于当前中点求积。

常介质的闭式解 `T=exp(−σd)`、`L=j(1−T)/σ` 已用于现有每步积分与小光学厚度处理。不能把整段变化的高度、光源透射和遮挡当常量，从而声称一步等价替代 16 步。

分段线性高度消光可沿球面半径解析积分，原函数包含 `0.5*(u*sqrt(u²+k²)+k²*asinh(u/k))`。它需要按介质节点与射线转向点拆段，且存在差分稳定性和特殊函数成本。适合作为精度参考，暂不列为直接 GPU 加速方案。

## 可复用的输运代数

有限段用 (T,L) 表示，先经过近段 A 再经过远段 B：

```
(TA,LA) ∘ (TB,LB) = (TA*TB, LA + TA*LB)
```

该运算在实数中具有结合律，可支持前缀积分、分块或层级复用。顺序、RGB/光谱通道、光源与介质状态必须保留。运动、几何遮挡与透明阴影使缓存失效范围复杂；插值、降分辨率和跨像素复用是另加的近似。当前光谱到 RGB 的非负 clamp 也不能任意移到累加后。NRD、曝光与色调映射并不普遍满足此结合律，不可随意交换合成顺序或重复乘 T。

## 采样稳定性与浮点约束

- 太阳采样 `:365` 仍通过 `sqrt(1−cos²θ)` 得到 sinθ。小圆盘下可先算 `δ=(1−u)*2*sin²(α/2)`，再算 `sinθ=sqrt(δ*(2−δ))`，避免接近 1 的消减。这是数值稳定性修复，需让方向、solid angle、命中判定一致。
- GGX VNDF 应按视线条件采样，匹配 proposal PDF；不能只换随机方向函数。依据见 [PBRT 可见微表面法线](https://pbr-book.org/4ed/Reflection_Models/Roughness_Using_Microfacet_Theory)。
- 同 receiver 的 alpha、F0、NdotV、G1(view)、太阳基向量等可预计算，但跨 trace 活跃值会增加寄存器。先检查编译器输出，再测 GPU 时间。
- Sobol 的同像素/epoch/vertex 公共 hash 可共享；bounce 和体积 vertex domain 改变时必须更新。不能破坏随机维度隔离。
- 当前 Rec.2020 throughput 使用 BT.709 luminance 做 RR。重新加权的 RR 不因此自动产生能量偏差，但可能影响彩色路径效率。
- sRGB 解码不能无条件搬到贴图加载前：`decode(filter(tex))` 与 `filter(decode(tex))` 不相等。近似 pow、统一 epsilon 或半精度不是自动等价优化。

## CPU 与材质范围

POM 的取模与平坦高度证明属于直接候选。光树 radix、输入复用、材质洞分配树和增量 section merge 已有实现。相机跨 chunk 的窗口差集条带可把空间更新从 O(R²S) 降至 O(RS|δ|)，但还需维护实际 chunk load/unload 和距离变化；它改善移动尖峰，不能解释主要 PT GPU 耗时。

光树 bottom-up power 合并会改变浮点求和顺序，quickselect 会改变拓扑和随机分布；不得归为逐样本相同优化。POM DDA 加解析二次交点改变离散首次交点算法，也可能在掠射角变慢。详细边界见 [CPU 与材质审计](rt-math-cpu-material-audit-2026-10-04.md)。
